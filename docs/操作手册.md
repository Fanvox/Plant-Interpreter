## 第 0 步：买零件

淘宝/拼多多直接搜索，总价 **35~45 元**，全部不需要焊接：

| # | 零件 | 搜索词 | 参考价 | 备注 |
|---|------|--------|--------|------|
| 1 | ESP32 开发板 | `ESP32-WROOM-32 开发板 CP2102` | ~20 元 | 一定带 **CP2102**（串口芯片），否则烧录麻烦 |
| 2 | 土壤湿度传感器 | `电容式土壤湿度传感器 v1.2` | ~5 元 | **必须电容式！** 图片上是绿色一字形 PCB 的是电容式；叉子形状两个金属脚的是电阻式，别买 |
| 3 | 温湿度模块 | `DHT11 模块 单总线` | ~4 元 | 买"模块"版（带小 PCB 板），不买裸传感器 |
| 4 | 杜邦线 | `杜邦线 母对母 20cm 40根` | ~3 元 | 传感器和开发板都是排针，母对母直插 |
| 5 | USB 数据线 | Micro-USB 数据线 | 0~5 元 | 很多开发板赠送。注意是**数据线**不是纯充电线 |

**验收**：零件到手后，ESP32 插 USB 电脑能听到"叮咚"设备接入声；传感器金属区域是绿色、无外露金属叉。

## 第 1 步：搭软件环境

### 1.1 Arduino IDE（写 ESP32 程序）

1. 官网下载 **Arduino IDE 2.x**（Windows 版），一路下一步安装。
2. 添加 ESP32 板卡支持：
   - `文件 → 首选项 → 其他开发板管理器地址`，填入：
     ```
     https://espressif.github.io/arduino-esp32/package_esp32_index.json
     ```
   - `工具 → 开发板 → 开发板管理器`，搜索 `esp32`，安装 **esp32 by Espressif Systems**（需几分钟）。
3. 安装串口驱动：插上 ESP32，若设备管理器看不到 COM 口，搜索安装 `CP210x 驱动`。
4. 安装库：`工具 → 管理库`，搜索安装：
   - `DHT sensor library`（选 Adafruit 的，提示装依赖就全部安装）

### 1.2 Python（跑后端）

```bash
# 电脑上已装 Python 3.10+ 的话，进入 code/backend 目录：
pip install -r requirements.txt
```

### 1.3 注册两个免费账号（现在就做，避免中途卡住）

| 账号 | 用途 | 入口 |
|------|------|------|
| **Server酱** | 推送到微信 | sct.ftqq.com → 微信扫码登录 → 复制你的 **SendKey** |
| **智谱开放平台** | LLM 文案 | open.bigmodel.cn → 注册 → 控制台创建 **API Key**（glm-4-flash 模型免费） |

## 第 2 步：接线

**断电操作！** 拔掉 USB 再接线，接完检查一遍再通电。

```
电容式土壤传感器          ESP32
┌────────────┐
│ VCC ──────────────────→ 3.3V
│ GND ──────────────────→ GND
│ AOUT ─────────────────→ GPIO 34
└────────────┘

DHT11 模块
│ VCC ──────────────────→ 3.3V（有的模块标 3V3）
│ GND ──────────────────→ GND
│ DATA ─────────────────→ GPIO 4
```

- GPIO34 在开发板右侧一排引脚上，丝印写着 `34`；3.3V 丝印是 `3V3` 或 `3.3V`。
- 土壤传感器**只插一半深度**进土里（线朝上），别没过电子部分。
- 通电后 ESP32 板上蓝色小灯闪 = 正常。

## 第 3 步：传感器标定

这一步决定数据准不准，**5 分钟但必须做**：

1. 打开 Arduino IDE，随便新建一个空程序（或先烧录第 4 步代码也行），在串口监视器（波特率 115200）看 ADC 原始值。
2. 临时在 `loop()` 里加 `Serial.println(analogRead(34)); delay(500);` 烧录。
3. **记两个数**：
   - 传感器**悬空**（干燥空气）→ 记为 `CALIB_DRY`（通常 2600~3400）
   - 传感器**完全插进一杯水里**（只露出线）→ 记为 `CALIB_WET`（通常 1100~1500）
4. 把这两个数填进 `plant_interpreter.ino` 顶部的对应常量。

> 不同传感器个体差异大，所以必须用自己的实测值，代码里的默认值只是占位。

## 第 4 步：点亮 ESP32

打开 `code/esp32/plant_interpreter.ino`，**改顶部 3 处配置**：

```cpp
const char* WIFI_SSID  = "你的WiFi名";
const char* WIFI_PASS  = "你的WiFi密码";
const char* SERVER_URL = "http://192.168.x.x:5000/data";  // 下一节查IP
```

**查电脑局域网 IP**（ESP32 和电脑必须连同一个 Wi-Fi）：

```bash
# Git Bash / CMD 里执行：
ipconfig
# 找 "无线局域网适配器 WLAN" 下的 IPv4 地址，例如 192.168.1.100
# SERVER_URL 就填 http://192.168.1.100:5000/data
```

**烧录**：

1. `工具 → 开发板` 选 `ESP32 Dev Module`；`工具 → 端口` 选出现的 COM 口。
2. 点左上角"→"上传按钮。第一次烧录 ESP32 会卡在 `Connecting...`，此时**按住板子上 BOOT 键不放直到开始写入**（有的板子不用按，卡住再按）。
3. 打开串口监视器（115200），按一下板上 RST 键，看到：

```
连接WiFi....
WiFi已连接, IP: 192.168.1.42
```

✅ **第 1 周里程碑 1 达成：硬件上线。**

> 💡 调试期把 `UPLOAD_MS` 换成注释里的 1 分钟那行，测完再改回 30 分钟。

## 第 5 步：跑通后端，数据上传

1. 打开 `code/backend/app.py`，暂时不用改任何配置（先跑起来）。
2. 启动：

```bash
cd code/backend
python app.py
# 看到 * Running on http://0.0.0.0:5000 即成功
```

3. 等 ESP32 下一次上传（调试模式 1 分钟内），后端终端出现：

```
[14:32:05] soil=47% state=fine
```

✅ **第 1 周里程碑 2 达成：数据闭环跑通。**

**若收不到，按顺序排查（详见附录 A）：**

- Windows 防火墙拦了 5000 端口 → 首次运行时弹窗选"允许"；或手动放行 Python。
- ESP32 和电脑不在同一 Wi-Fi（校园网经常隔离设备！）→ 换手机热点试。
- 手机开热点测试时，电脑也连这个热点，`SERVER_URL` 要改成电脑在新网络下的 IP。

> ⚠️ **校园网注意**：校园 Wi-Fi 常开"AP 隔离"，设备之间互相不可见。宿舍路由器没问题；实在不行就用手机开热点，让 ESP32 和电脑都连热点，这也是答辩演示时最稳的方案。

## 第 6 步：LLM 文案 + 微信推送（第 2 周）

1. 在 `app.py` 顶部填入第 1.3 步申请的两个 Key：

```python
SENDKEY = "SCTxxxxxx你的SendKey"
LLM_API_KEY = "你的智谱APIKey"
```

2. 想调植物人设，改这三行：

```python
PLANT_NAME = "小绿"
PLANT_TYPE = "绿萝"
PUSH_MAX_PER_DAY = 5
```

3. 重启后端，然后**做一次真实测试**：把传感器从土里拔出来晾在空气里（湿度会掉到 0%，模拟"严重缺水"），等下一轮上传，手机应收到微信推送，例如：

> **小绿｜严重缺水**
> 主人……我都干成标本了，你的绿萝不是仙人掌啊呜呜呜
> 土壤湿度 3% · 11-15 21:04

4. 再把传感器插回浇过水的土里（湿度冲到 85%+），应收到"刚喝饱水"的感谢文案。

✅ **第 2 周里程碑达成：传感器变化 → 手机收到性格文案。**

**推送逻辑说明（给学长讲的时候用得上）**：

- 状态变化才推送（不刷屏）：`fine → thirsty` 发一条，持续 `thirsty` 不再发；
- 严重缺水时每 6 小时催一次（防主人装死）；
- 每日上限 5 条（防 LLM 额度刷爆）；
- LLM 失败自动降级为固定格式文案，**通知功能永不因 AI 挂掉而失效**——这就是"模型挂了系统不能挂"的工程思想。

## 附录 A：故障排查表

| 症状 | 可能原因 | 解决 |
|------|---------|------|
| 串口监视器无输出 | 波特率不对 | 监视器右下角选 115200 |
| 卡在 Connecting... | 需要手动进烧录模式 | 按住 BOOT 键再点上传 |
| 找不到 COM 口 | 缺 CP2102 驱动 | 装 CP210x 驱动 |
| WiFi 连不上 | 5G Wi-Fi 不支持 | ESP32 只支持 2.4GHz，路由器开"双频"或连 2.4G 那个 |
| WiFi 连不上 | 密码含中文/特殊字符 | 换简单密码测试 |
| 后端收不到数据 | 防火墙 | 允许 Python 通过 Windows 防火墙 |
| 后端收不到数据 | 校园网设备隔离 | 换手机热点（最稳） |
| 后端收不到数据 | SERVER_URL 的 IP 变了 | 重新 ipconfig，改代码重新烧录 |
| DHT 读数 NaN | DHT11 采样间隔太短 | DHT11 最快 1 秒一次，代码已含 delay，报 NaN 就检查接线 |
| 湿度一直 0% 或 100% | 没标定 | 回到第 3 步重新记 CALIB_DRY / CALIB_WET |
| 微信收不到推送 | SendKey 错 / Server酱未绑定 | sct.ftqq.com 检查"微信推送"测试按钮 |
| LLM 报 401 | API Key 错或未充值 | 智谱控制台检查；glm-4-flash 免费 |
| 电脑关机后断更 | 后端在电脑上跑 | 正常现象；进阶可部署到 5 元/月的学生云服务器 |

## 附录 B：常见坑

1. **买错传感器**：电阻式（两金属叉）几周内会被电解腐蚀失效，认准电容式。
2. **传感器插太深**：电子部分入土会受潮短路，只插金属区域一半。
3. **数据别只有湿度**：空气温湿度是 LLM 叙事的素材（"今天好冷我不想喝水"），DHT11 四块钱别省。
4. **先标定再上线**：默认标定值是占位符，没标定的曲线图拿不出手。
5. **每周给学长同步一次进度**：哪怕只发"这周点亮了硬件，下周跑推送"，可靠感 > 聪明感。
6. **答辩演示用手机热点**：现场 Wi-Fi 不可控，热点是唯一稳的演示环境，提前演练一遍。
